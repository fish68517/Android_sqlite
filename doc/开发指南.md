# Android 自动截屏后台辅助工具开发指南

本文档基于 `需求描述.txt` 编写，目标是在 Android Studio 中使用 Java 开发一个学习用途的 Android App：用户阅读其他 App 内容时，本工具在授权后后台运行，监听翻页或内容变化，获取当前页面内容，调用大模型生成简短总结，并以顶部悬浮窗展示，不打断当前阅读流程。

> 重要边界：Android 不能在完全无感、未授权的情况下后台截屏或读取其他 App 内容。首次使用必须由用户主动授予无障碍服务、悬浮窗、前台服务通知、屏幕录制等权限。授权完成后，应用可以在前台服务存活期间尽量做到不打断用户阅读。

## 1. 需求拆解

### 1.1 核心目标

- App 启动后可退至后台，通过前台服务保持核心流程运行。
- 用户在阅读 App 中翻页、滚动或内容变化时，自动触发内容获取。
- 优先通过无障碍服务读取当前页面文字；读取失败或内容不足时，回退到 MediaProjection 屏幕截图。
- 将文字或截图发送到大模型 API，要求模型只返回最终总结，不返回推理过程。
- 在屏幕顶部显示半透明悬浮消息条，几秒后自动隐藏，也支持手动滑走。
- 针对 MIUI 和 Android 16 设备提供授权引导和保活设置说明。
- 通过请求编号、页面指纹、超时和取消机制，避免“上一页总结显示到下一页”的错位问题。

### 1.2 推荐实现策略

采用“双通道内容获取”：

1. 无障碍文字通道作为主路径：速度快、流量小、无需频繁上传截图。
2. 截图视觉通道作为兜底路径：当阅读 App 无法暴露文字节点、内容为空、图片型文档或 OCR 场景时使用。

触发策略采用“事件触发 + 节流 + AI 返回后延迟再取”：

- 无障碍事件检测到 `TYPE_VIEW_SCROLLED`、`TYPE_WINDOW_CONTENT_CHANGED`、`TYPE_WINDOW_STATE_CHANGED` 后，延迟 800-1200ms 等页面稳定，再生成页面快照。
- 如果 AI 正在请求中，新页面到来时取消旧请求或标记旧请求过期。
- AI 返回后默认等待 5 秒再允许下一次自动截图，避免连续刷屏和费用失控。

## 4. 本地配置

### 4.1 `local.properties`

在项目根目录的 `local.properties` 中配置密钥和模型。不要把真实密钥写进 Markdown、Java 代码或 Git 仓库。

```properties
GLM_API_KEY=replace_with_your_glm_api_key
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
GLM_TEXT_MODEL=glm-5.2
GLM_VISION_MODEL=glm-4v-plus
GLM_KNOWLEDGE_ID=2070110061119811584

KIMI_API_KEY=
KIMI_BASE_URL=https://api.moonshot.ai/v1
KIMI_MODEL=

AI_REQUEST_TIMEOUT_SECONDS=20
AI_SUMMARY_MAX_CHARS=80
```

注意：`local.properties` 不提交到仓库只能避免源码泄漏。通过 `BuildConfig` 打进 APK 的 Key 仍然可以被逆向得到，所以该方案只适合学习项目。正式产品应改为后端代理：Android 端只请求自己的服务端，由服务端保存和调用大模型密钥。

### 4.2 Gradle 读取配置

在 `app/build.gradle` 中读取 `local.properties` 并生成 `BuildConfig` 字段：

```gradle
def localProps = new Properties()
def localPropsFile = rootProject.file("local.properties")
if (localPropsFile.exists()) {
    localPropsFile.withInputStream { stream -> localProps.load(stream) }
}

android {
    namespace 'com.example.readingassistant'

    buildFeatures {
        buildConfig true
    }

    defaultConfig {
        applicationId "com.example.readingassistant"
        minSdk 26
        targetSdk 36

        buildConfigField "String", "GLM_API_KEY", "\"${localProps.getProperty("GLM_API_KEY", "")}\""
        buildConfigField "String", "GLM_BASE_URL", "\"${localProps.getProperty("GLM_BASE_URL", "https://open.bigmodel.cn/api/paas/v4")}\""
        buildConfigField "String", "GLM_TEXT_MODEL", "\"${localProps.getProperty("GLM_TEXT_MODEL", "glm-5.2")}\""
        buildConfigField "String", "GLM_VISION_MODEL", "\"${localProps.getProperty("GLM_VISION_MODEL", "glm-4v-plus")}\""
        buildConfigField "String", "GLM_KNOWLEDGE_ID", "\"${localProps.getProperty("GLM_KNOWLEDGE_ID", "")}\""

        buildConfigField "String", "KIMI_API_KEY", "\"${localProps.getProperty("KIMI_API_KEY", "")}\""
        buildConfigField "String", "KIMI_BASE_URL", "\"${localProps.getProperty("KIMI_BASE_URL", "https://api.moonshot.ai/v1")}\""
        buildConfigField "String", "KIMI_MODEL", "\"${localProps.getProperty("KIMI_MODEL", "")}\""

```

依赖建议：

```gradle
dependencies {
    implementation "com.squareup.okhttp3:okhttp:4.12.0"

```

如需更方便地构造 JSON，可以额外引入 Gson；学习项目也可以直接使用 Android 自带的 `org.json`。

## 6. 启动与授权流程

`MainActivity` 做成一个简单的权限面板：

1. 检查悬浮窗权限：`Settings.canDrawOverlays(context)`。
2. 检查无障碍服务是否启用。
3. Android 13 及以上检查通知权限。
4. 引导用户关闭电池优化。
5. 引导 MIUI 用户开启自启动、后台运行、锁屏显示、悬浮窗等权限。
6. 点击“开始辅助”后申请 MediaProjection 屏幕录制授权。
7. 授权成功后启动 `CaptureForegroundService`，并把 `resultCode` 和 `data Intent` 传给服务。

MediaProjection 必须通过系统弹窗让用户确认，不能静默绕过。Android 14 及以上还要求前台服务声明合适的类型；Android 15 及以上对从后台启动前台服务和悬浮窗可见性有更严格限制，因此建议所有核心流程都由 `MainActivity` 的用户点击启动。

## 7. 后台前台服务设计

`CaptureForegroundService` 负责保活和调度：

- 启动后立即调用 `startForeground()` 显示常驻通知。
- 初始化 `MediaProjectionController`。
- 注册与 `ReaderAccessibilityService` 的本地通信，例如通过单例协调器、`LocalBroadcastManager` 替代方案或进程内回调。
- 持有 `CaptureCoordinator`，统一处理页面变化、截图、请求取消和结果展示。
- 服务停止时释放 VirtualDisplay、ImageReader、MediaProjection、网络请求和悬浮窗。

通知内容建议保持克制：

- 标题：阅读总结辅助运行中
- 内容：点击返回设置，停止请在应用内关闭
- 操作按钮：停止

## 8. 内容获取方案

### 8.1 无障碍文字提取

`ReaderAccessibilityService.onAccessibilityEvent()` 中处理页面变化：

```java
@Override
public void onAccessibilityEvent(AccessibilityEvent event) {
    int type = event.getEventType();
    if (type == AccessibilityEvent.TYPE_VIEW_SCROLLED
            || type == AccessibilityEvent.TYPE_WINDOW_CONTENT_CHANGED
            || type == AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED) {
        AccessibilityNodeInfo root = getRootInActiveWindow();
        PageSnapshot snapshot = TextNodeExtractor.fromRoot(root, event.getPackageName());
        CaptureCoordinator.getInstance().onPageMaybeChanged(snapshot);
    }
}
```

提取规则：

- 递归读取 `node.getText()` 和必要的 `node.getContentDescription()`。
- 过滤按钮、广告、导航栏、状态栏、过短文本和重复文本。
- 合并为一段正文，保留自然段分隔。
- 对正文做归一化和 hash，作为页面指纹。
- 如果正文少于 50-100 个有效汉字，标记为 `TEXT_TOO_SHORT`，交给截图通道兜底。

### 8.2 MediaProjection 截图

截图流程：

1. 从 `MainActivity` 获取 MediaProjection 授权结果。
2. 服务中通过 `MediaProjectionManager.getMediaProjection(resultCode, data)` 创建 `MediaProjection`。
3. 使用 `ImageReader.newInstance(width, height, PixelFormat.RGBA_8888, 2)`。
4. 使用 `mediaProjection.createVirtualDisplay()` 把屏幕渲染到 `ImageReader.getSurface()`。
5. 调用 `imageReader.acquireLatestImage()` 取最新帧。
6. 转成 `Bitmap`，裁剪多余 stride，压缩为 JPEG。
7. 下采样到合适尺寸，例如最长边 1280，质量 70-80，转 Base64。

截图前建议临时隐藏自己的悬浮窗，避免把总结条也截进图片。截图失败时最多重试一次；如果 MediaProjection 已被系统停止，回到主界面重新授权。

### 8.3 页面指纹

每次生成 `PageSnapshot` 时记录：

- `sequenceId`：递增请求编号。
- `packageName`：当前前台 App。
- `contentHash`：文本 hash 或截图感知 hash。
- `capturedAt`：捕获时间。
- `sourceType`：`ACCESSIBILITY_TEXT` 或 `SCREENSHOT_IMAGE`。
- `preview`：前 20-30 个字，用于调试和错位判断，不直接展示给用户。

AI 结果返回时，只允许最新 `sequenceId` 展示。如果期间页面指纹变了，旧结果丢弃，或以“上一页总结”样式弱提示；默认建议直接丢弃，降低错位干扰。

## 9. AI 调用设计

### 9.1 Prompt

系统 Prompt：

```text
你是一个阅读辅助总结器。请在内部完成充分理解和推理，但最终只输出最终结论。
输出必须满足：
1. 只输出一行，以“总结：”开头。
2. 不输出分析过程、推理步骤、引用列表、免责声明或多余前后缀。
3. 总结不超过80个中文字符。
4. 如果内容无法识别，输出“总结：当前页面内容不足，暂无法总结。”
```

用户 Prompt：

```text
请总结当前阅读页面的核心意思。只返回最终总结。
```

如果使用文本通道，把提取到的正文附在用户消息后。如果使用截图通道，把截图作为 `image_url` 内容传入视觉模型。

### 9.2 GLM 文本请求

接口：

```text
POST {GLM_BASE_URL}/chat/completions
Authorization: Bearer {GLM_API_KEY}
Content-Type: application/json
```

请求体示例：

```json
{
  "model": "glm-5.2",
  "messages": [
    {
      "role": "system",
      "content": "你是一个阅读辅助总结器。请在内部完成充分理解和推理，但最终只输出最终结论。输出必须以“总结：”开头，不超过80个中文字符。"
    },
    {
      "role": "user",
      "content": "请总结当前阅读页面的核心意思。只返回最终总结。\n\n页面正文：..."
    }
  ],
  "thinking": {
    "type": "enabled"
  },
  "temperature": 0.2,
  "max_tokens": 120
}
```

解析时只读取 `choices[0].message.content`，不要展示任何推理字段。如果返回内容不以 `总结：` 开头，客户端二次规整为 `总结：{content}`。

### 9.3 GLM 视觉请求

视觉模型请求体示例：

```json
{
  "model": "glm-4v-plus",
  "messages": [
    {
      "role": "system",
      "content": "你是一个阅读辅助总结器。最终只输出一行“总结：...”"
    },
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "请阅读图片中的页面内容，返回不超过80个中文字符的最终总结。不要输出推理过程。"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/jpeg;base64,{BASE64_IMAGE}"
          }
        }
      ]
    }
  ],
  "temperature": 0.2,
  "max_tokens": 120
}
```

如果需要使用已上传知识库，建议先按智谱当前知识库接口确认具体参数名和调用方式，再在 `GlmClient` 中封装，不要把知识库字段散落在业务代码里。配置项 `GLM_KNOWLEDGE_ID` 只作为集中配置入口。

### 9.4 Kimi 降级

Kimi 配置为空时不启用。启用后流程：

1. GLM 请求网络错误、超时或服务端 5xx 时，尝试 Kimi。
2. 如果 Kimi 只配置了文本模型，则只对无障碍文本通道降级。
3. 降级结果同样必须经过 `SummaryParser` 校验和截断。

Kimi API 的请求/响应格式兼容 OpenAI Chat Completions，Java 端可以复用 `AiClient` 的大部分请求构造逻辑，只替换 `baseUrl`、`apiKey` 和 `model`。

## 10. 网络与错位控制

`CaptureCoordinator` 是关键模块，建议实现以下状态机：

```text
IDLE
  -> PAGE_CHANGED_DEBOUNCING
  -> CAPTURING
  -> REQUESTING_AI
  -> DISPLAYING
  -> COOLDOWN
  -> IDLE
```

控制规则：

- Debounce：页面变化后等待 800-1200ms，期间如果继续变化，重新计时。
- Cancel：新页面指纹出现时，取消旧 OkHttp `Call`。
- Timeout：AI 总超时建议 15-20 秒，超过后丢弃，不弹错误悬浮窗。
- Latest only：只展示最新 `sequenceId` 的结果。
- Cooldown：展示结束后至少 5 秒再触发下一次获取。
- Duplicate skip：同一 `contentHash` 在 30 秒内不重复请求。
- Cost guard：连续失败 3 次后暂停 60 秒，避免异常状态下持续烧额度。

## 11. 悬浮窗设计

`FloatingSummaryWindow` 使用 `WindowManager` 添加顶部 View：

- Window 类型：`TYPE_APPLICATION_OVERLAY`
- Gravity：`TOP | CENTER_HORIZONTAL`
- 宽度：屏幕宽度的 92%-96%
- 高度：`WRAP_CONTENT`
- 背景：半透明深色或浅色，圆角小于等于 8dp
- 文本：最多 2 行，超过省略
- 行为：4-6 秒自动消失；横向滑动或上滑关闭

参数建议：

```java
WindowManager.LayoutParams params = new WindowManager.LayoutParams(
        WindowManager.LayoutParams.MATCH_PARENT,
        WindowManager.LayoutParams.WRAP_CONTENT,
        WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY,
        WindowManager.LayoutParams.FLAG_NOT_FOCUSABLE
                | WindowManager.LayoutParams.FLAG_NOT_TOUCH_MODAL
                | WindowManager.LayoutParams.FLAG_LAYOUT_IN_SCREEN,
        PixelFormat.TRANSLUCENT
);
params.gravity = Gravity.TOP | Gravity.CENTER_HORIZONTAL;
```

如果完全不需要手动滑走，可以增加 `FLAG_NOT_TOUCHABLE` 让触摸穿透；但这样用户无法滑动关闭。推荐保持悬浮条很矮，只消费悬浮条区域内的滑动，不影响阅读 App 的主体操作。

## 12. MIUI 与国产系统适配

MIUI 需要在应用内给出清晰的授权状态，不要假设系统会自动放行后台行为。

建议提供“权限检查”页面：

- 悬浮窗权限：跳转 `ACTION_MANAGE_OVERLAY_PERMISSION`。
- 无障碍权限：跳转 `Settings.ACTION_ACCESSIBILITY_SETTINGS`。
- 通知权限：Android 13 及以上动态申请。
- 忽略电池优化：跳转 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。
- MIUI 自启动：尝试跳转 MIUI 安全中心对应页面，失败则展示文字路径。
- 后台弹出界面、锁屏显示、后台运行无限制：展示人工开启说明。

实际兼容时要接受一个事实：不同 MIUI 版本设置入口经常变化，代码跳转不能保证 100% 成功，所以页面必须同时提供文字路径。

## 13. 日志与隐私

- 日志中禁止打印完整 API Key，只允许显示前后各 3 位，例如 `abc***xyz`。
- 不在本地长期保存截图；调试保存截图时只放 debug 构建，并提供一键清理。
- 不上传与阅读页面无关的全屏信息；能用无障碍文本就不要截图。
- 悬浮窗展示前对模型结果做长度限制，避免返回异常长文本遮挡屏幕。
- 如果页面包含密码、支付、聊天隐私等敏感场景，应通过包名黑名单暂停截图和上传。

建议黑名单：

```text
com.android.settings
com.miui.securitycenter
com.tencent.mm
com.eg.android.AlipayGphone
银行类 App 包名
密码管理器包名
```

学习项目可先手动维护，后续再做用户可配置。

## 14. 开发里程碑

### 阶段 1：项目骨架和权限页

- 新建 Android Studio Java 项目。
- 完成 `MainActivity` 权限检查列表。
- 完成通知权限、悬浮窗设置页、无障碍设置页跳转。
- 完成前台服务启动和停止。

验收：启动服务后退到后台，通知常驻，点击通知可回到 App。

### 阶段 2：悬浮窗 MVP

- 实现 `FloatingSummaryWindow.show(text)`。
- 支持顶部展示、自动隐藏、手动滑走。
- 验证不抢输入焦点，不影响阅读 App 翻页。

验收：在任意 App 上方显示 `总结：测试内容`，几秒后消失。

### 阶段 3：无障碍文字通道

- 实现 `ReaderAccessibilityService`。

- 实现 `GlmClient` 文本总结。
- 实现 `GlmClient` 视觉总结。

- 实现超时、取消、失败重试和 Kimi 可选降级。

### 阶段 6：错位治理

- 实现 `sequenceId` 最新结果校验。
- 新页面出现时取消旧请求。
- 实现 5 秒 cooldown 和重复页面跳过。
- 模拟弱网和快速翻页，验证不会显示明显过期结果。

验收：连续快速翻 5 页，只展示最后一页或当前页总结。

### 阶段 7：MIUI 真机适配

- 在目标 MIUI 设备上逐项验证权限。
- 记录不同设置入口。
- 验证锁屏、清后台、长时间阅读、电池优化后的存活情况。

验收：授权完整后，至少连续阅读 30 分钟，服务不异常退出，悬浮窗稳定展示。

## 17. 常见问题

### 17.1 能否完全静默截屏？

不能。MediaProjection 必须经过系统授权，且新版本 Android 会明显提示用户正在录屏或投屏。学习项目可以在用户授权后保持会话，但不能绕过系统提示。

### 17.2 为什么优先用无障碍文字？

文字通道更快、更省流量，也更容易避免上传整屏隐私信息。截图适合文字节点拿不到、图片型页面、漫画或扫描版文档等场景。

### 17.3 为什么 API Key 放在 `local.properties` 仍不安全？

`local.properties` 可以避免提交源码时泄漏，但 Gradle 生成的 `BuildConfig` 会进入 APK。别人拿到 APK 后仍可能逆向出 Key。正式项目必须使用后端代理。

### 17.4 知识库 ID 怎么使用？

先把知识库 ID 作为配置项保留。具体调用字段要以智谱当前知识库 API 文档为准，建议封装在 `GlmClient` 内部，不要让业务层感知知识库接口细节。
