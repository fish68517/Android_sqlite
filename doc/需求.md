### **项目名称：** 校园健康管理卫士App

### **项目简介**
这是一款面向校园用户的健康管理应用，旨在帮助学生、老师等用户群体更好地管理个人健康，提供便捷的校园健康服务功能。

### **技术栈选型**
*   **开发环境 (IDE):** Android Studio
*   **开发语言:** Java
*   **数据库:** SQLite
*   **数据实现:** 核心业务数据（如用户信息、打卡记录）存储在本地SQLite数据库中；部分动态数据（如步数、运动数据）采用模拟数据或用户手动输入的方式，以简化开发。

---

### **功能需求规划 (Function Requirement)**

根据你的思维导图，我们将App功能分为以下几个核心模块：

#### **1. 用户模块 (User Module)**

这是App的基础，用于管理不同的用户角色。

*   **用户注册与登录:**
    *   提供注册界面，用户可以选择角色（学生、老师、医生、管理员）。
    *   提供登录界面，允许多角色登录。
    *   用户信息（账号、密码、角色）存储在本地SQLite的`user`表中。
*   **用户角色区分:**
    *   **学生/老师:** 可以使用App的所有核心健康功能。
    *   **医生:** （简化版）可以查看预约信息（此功能为模拟，医生端暂不开发复杂后台）。
    *   **管理员:** （简化版）拥有最高权限，可以管理用户信息（此功能为模拟，暂不开发复杂后台）。

#### **2. 核心功能模块 (Core Function Module)**

这部分是App的主要功能集合。

*   **每日打卡:**
    *   一个简单的界面，用户可以点击“打卡”按钮记录当天健康状况（如体温正常、无不适等）。
    *   打卡记录（用户ID、打卡日期）存储在SQLite的`checkin`表中。
*   **预约就诊:**
    *   提供一个表单，用户可以选择预约时间、科室（如内科、外科等，固定选项即可）和填写简要病情。
    *   提交后的预约信息存入SQLite的`appointment`表中。用户可以查看自己的预约记录。
*   **通行码:**
    *   一个简单的静态页面，显示一个绿色的二维码图片和当前时间。
    *   这个功能为模拟，不需要与后台数据校验，仅用于展示。
*   **消息通知:**
    *   创建一个列表页面，用于显示“通知”。
    *   通知内容可以预先写在代码里，作为模拟数据展示。例如，“秋季流感预防通知”、“健康饮食讲座通知”等。

#### **3. 饮食健康模块 (Dietary Health Module)**

帮助用户管理日常饮食。

*   **营养打卡:**
    *   用户可以手动记录三餐内容（如早餐：牛奶、面包）。
    *   记录存储在SQLite的`diet`表中。
*   **食堂卡路里:**
    *   创建一个食物列表，展示常见食堂菜品及其估算的卡路里。
    *   这些数据可以预先存放在一个`food`表中，或者直接在代码中写成一个静态列表。
*   **饮食建议:**
    *   根据用户选择的身体状况（如“减肥”、“增肌”），显示一些静态的、预设好的饮食建议文本。

#### **4. 运动健身模块 (Sports & Fitness Module)**

这部分全部采用模拟数据，方便开发。

*   **步数统计:**
    *   在主界面显示一个步数。这个步数可以通过一个随机数生成，或者允许用户手动输入一个数字来模拟。
    *   不需要调用手机的计步传感器，大大降低开发难度。
*   **运动打卡:**
    *   提供一个运动项目列表（如跑步、篮球、游泳）。
    *   用户选择一项运动并点击“打卡”，记录将保存到SQLite的`exercise`表中。
*   **健身计划:**
    *   提供几个预设的健身计划模板（如“周一练胸”、“周二练背”）。
    *   用户可以查看这些计划，无需复杂的自定义功能。

### **数据库设计 (SQLite Database Design)**

根据以上功能，你可以设计以下几张简单的表：

1.  **用户信息表 (user_table)**
    *   `id` (主键, 自增)
    *   `username` (用户名)
    *   `password` (密码)
    *   `role` (用户角色: 学生, 老师等)

2.  **每日打卡表 (checkin_table)**
    *   `id` (主键, 自增)
    *   `user_id` (用户ID)
    *   `checkin_date` (打卡日期)

3.  **预约就诊表 (appointment_table)**
    *   `id` (主键, 自增)
    *   `user_id` (用户ID)
    *   `department` (科室)
    *   `appointment_time` (预约时间)
    *   `description` (病情描述)

4.  **饮食记录表 (diet_table)**
    *   `id` (主键, 自增)
    *   `user_id` (用户ID)
    *   `meal_type` (餐别: 早餐, 午餐, 晚餐)
    *   `food_content` (食物内容)
    *   `record_date` (记录日期)

5.  **运动打卡表 (exercise_table)**
    *   `id` (主键, 自增)
    *   `user_id` (用户ID)
    *   `exercise_type` (运动类型)
    *   `exercise_date` (运动日期)

### **开发建议**

*   **分步开发:** 不要试图一次性完成所有功能。可以先从“用户模块”开始，然后逐一实现“每日打卡”、“步数统计”等简单功能。
*   **界面简洁:** 作为学生项目，重点是实现功能逻辑。UI界面可以使用Android Studio提供的标准控件，保持简洁即可。
*   **勤于测试:** 每完成一个小功能，就在模拟器或真机上运行测试，确保没有明显的Bug。

这个方案为你简化了许多复杂的后端和数据交互逻辑，让你能更专注于Android客户端的开发和学习。祝你项目顺利！如果开发中遇到具体问题，可以随时再来提问。
