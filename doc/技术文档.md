# 项目技术文档

本文档旨在详细说明学生信息管理App的技术实现方案，包括页面设计、数据库接口设计和核心功能设计。

## 1. 页面设计

App的核心由两个Fragment构成，用于展示和管理学生信息。

### 1.1. 学生信息列表页 (`StudentListFragment`)

-   **功能**: App的入口页面，以列表形式展示所有学生的基本信息（如：姓名、学号）。
-   **UI组件**:
    -   `RecyclerView`: 用于高效地展示学生列表。
    -   `FloatingActionButton` 或右上角菜单: 用于触发"新增学生"操作。
    -   空状态视图: 当列表为空时，显示引导用户新增信息的提示。
-   **交互**:
    -   点击列表中的任意一项，会跳转到该学生的详情页。
    -   点击新增按钮，会跳转到信息详情页（此时页面为新增模式）。

### 1.2. 学生信息详情页 (`StudentDetailFragment`)

-   **功能**: 用于显示、新增或编辑单个学生的详细信息。该页面可复用。
-   **模式**:
    -   **查看/编辑模式**: 从列表页点击学生项进入，页面会填充该学生的现有信息。信息字段可编辑。
    -   **新增模式**: 从列表页点击新增按钮进入，页面显示为空白表单。
-   **UI组件**:
    -   `ImageView`: 用于显示和选择学生头像。
    -   `EditText`: 用于输入/编辑学生的姓名、学号、手机号、个人简介。
    -   `Button`: 用于"保存"或"更新"信息。
    -   `Button`: 用于"删除"学生信息（仅在编辑模式下可见）。
-   **交互**:
    -   用户完成信息输入后，点击保存/更新按钮，数据将被写入数据库。
    -   操作完成后，页面自动返回到学生信息列表页，并刷新列表。
    -   支持使用系统的返回键或导航栏的返回按钮返回列表页。

## 2. 数据库接口设计

数据持久化采用Android原生的SQLite数据库，通过`OpenHelperDataBase`类进行管理。

### 2.1. `students` 表结构

| 字段名                 | 类型    | 约束                        | 描述           |
| ---------------------- | ------- | --------------------------- | -------------- |
| `_id`                  | INTEGER | PRIMARY KEY AUTOINCREMENT   | 主键ID         |
| `name`                 | TEXT    | NOT NULL                    | 学生姓名       |
| `student_id`           | TEXT    | NOT NULL UNIQUE             | 学号（唯一）   |
| `phone`                | TEXT    |                             | 手机号         |
| `bio`                  | TEXT    |                             | 个人简介       |
| `avatar_path`          | TEXT    |                             | 头像图片的路径 |

### 2.2. `OpenHelperDataBase.java` 核心接口

以下是在`OpenHelperDataBase.java`中为学生信息管理实现的核心方法：

-   `public long addStudent(Student student)`
    -   **功能**: 向`students`表中插入一条新的学生记录。
    -   **参数**: `Student`对象（不含id）。
    -   **返回**: 新记录的`_id`，失败则返回-1。

-   `public Student getStudent(long id)`
    -   **功能**: 根据主键`_id`查询单个学生的信息。
    -   **参数**: 学生记录的`_id`。
    -   **返回**: 包含该学生信息的`Student`对象，未找到则返回`null`。

-   `public List<Student> getAllStudents()`
    -   **功能**: 查询`students`表中的所有记录。
    -   **返回**: 包含所有学生对象的`List<Student>`列表。

-   `public int updateStudent(Student student)`
    -   **功能**: 根据`_id`更新一条已有的学生记录。
    -   **参数**: 包含新信息和`_id`的`Student`对象。
    -   **返回**: 受影响的行数。

-   `public boolean deleteStudent(long id)`
    -   **功能**: 根据`_id`删除一条学生记录。
    -   **参数**: 学生记录的`_id`。
    -   **返回**: 删除成功返回`true`，否则返回`false`。

## 3. 功能设计

### 3.1. 查看学生列表

1.  App启动后，`MainActivity`加载`StudentListFragment`。
2.  `StudentListFragment`调用`OpenHelperDataBase`的`getAllStudents()`方法获取所有学生数据。
3.  通过`RecyclerView.Adapter`将数据绑定到列表上进行展示。

### 3.2. 新增学生

1.  在`StudentListFragment`，用户点击新增按钮。
2.  导航到`StudentDetailFragment`（以"新增模式"启动，不传递学生ID）。
3.  用户在表单中输入信息，选择头像（可选）。
4.  点击"保存"按钮。
5.  `StudentDetailFragment`创建一个新的`Student`对象，并调用`OpenHelperDataBase`的`addStudent()`方法存入数据库。
6.  操作成功后，返回`StudentListFragment`。

### 3.3. 编辑学生信息

1.  在`StudentListFragment`，用户点击某个学生项。
2.  导航到`StudentDetailFragment`，并传递被点击学生的`_id`。
3.  `StudentDetailFragment`根据传入的`_id`，调用`getStudent()`方法获取学生数据并填充到UI控件中。
4.  用户修改信息后，点击"更新"按钮。
5.  `StudentDetailFragment`调用`updateStudent()`方法更新数据库。
6.  操作成功后，返回`StudentListFragment`。

### 3.4. 删除学生

1.  在`StudentDetailFragment`的编辑模式下，用户点击"删除"按钮。
2.  （建议）弹出一个确认对话框，防止误删。
3.  用户确认后，`StudentDetailFragment`调用`deleteStudent()`方法从数据库删除该记录。
4.  操作成功后，返回`StudentListFragment`。
