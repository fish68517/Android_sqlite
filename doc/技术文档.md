# 旅游APP技术架构文档

## 1. 引言

### 1.1. 项目概述
本项目是一个基于 Android 平台的旅游应用，旨在为用户提供一个集景点浏览、行程规划、旅游预订和动态分享于一体的综合性移动解决方案。用户可以通过本应用发现热门景点，规划和管理个人行程，预订旅游服务，并分享自己的旅游见闻。

### 1.2. 文档目的
本文档旨在详细阐述该旅游APP的整体技术架构、模块设计、数据库结构及核心技术选型，为后续的开发、维护和迭代提供清晰的技术指引和参考。

### 1.3. 读者对象
本文档主要面向项目开发人员、测试人员及项目管理者。

---

## 2. 系统概述

### 2.1. 核心功能
根据需求分析，系统需实现以下核心功能：
- **首页**：以网格布局展示推荐的热门景点列表。
- **景点详情页**：展示景点的图文详情，并提供预订入口。
- **预订页**：允许用户为特定景点创建预订。
- **行程管理页**：以列表形式展示用户创建的所有行程，并支持增、删、改、查操作。
- **个人动态页**：以列表形式展示用户的旅游动态分享。
- **个人中心页**：展示用户基本信息，提供"我的预订"和"退出登录"等功能。
- **多媒体播放**：应用内置背景音乐，并在主界面提供进度条进行播放控制。
- **数据持久化**：所有用户数据（如行程、预订、动态等）均通过本地 SQLite 数据库进行持久化存储和管理。

### 2.2. 技术栈
- **开发语言**：Java
- **目标平台**：Android
- **数据库**：SQLite
- **核心组件与库**：
  - **UI框架**：AndroidX (AppCompat, RecyclerView, CardView, BottomNavigationView)
  - **图片加载**：Glide
  - **数据库访问**：原生 `SQLiteOpenHelper`

## 3. 架构设计

### 3.1. 总体架构
本应用采用标准的 Android 组件化架构，逻辑上可以看作是简化的 **MVC (Model-View-Controller)** 模式，旨在实现业务逻辑、数据和用户界面的分离。

- **View (视图层)**：
  - 由 `Activity` 和 `Fragment` 组成，负责渲染UI和响应用户的交互操作。
  - XML 布局文件定义了静态的界面结构。
  - 主要组件包括：`MainActivity` (主容器)、`HomeFragment` (首页)、`ItineraryFragment` (行程)、`PostFragment` (动态)、`ProfileFragment` (我的)，以及多个功能性 `Activity`（如 `AttractionDetailActivity`, `AddItineraryActivity`, `MyBookingsActivity` 等）。

- **Controller (控制层)**：
  - 控制逻辑主要实现在 `Activity` 和 `Fragment` 中。它们作为视图和模型之间的桥梁，处理用户输入，调用模型层进行数据操作，并最终将结果更新到视图上。
  - `Adapter` 类 (如 `AttractionAdapter`, `BookingAdapter`) 也承担了一部分控制逻辑，负责将数据绑定到列表视图并处理列表项的点击事件。

- **Model (模型层)**：
  - **数据模型 (Data Models)**：定义了一系列 POJO (Plain Old Java Object) 类，如 `User`, `Attraction`, `Booking` 等，用于精确映射数据库中的数据表结构。
  - **数据访问对象 (Data Access Object)**：核心是 `OpenHelperDataBase.java` 类，它继承自 `SQLiteOpenHelper`，完全封装了对本地 SQLite 数据库的所有操作，包括数据库的创建、升级以及所有业务数据的增、删、改、查 (CRUD) 接口。

### 3.2. 导航流程
- 应用启动后，以 `MainActivity` 作为主界面。
- `MainActivity` 包含一个 `BottomNavigationView`，用于在 `HomeFragment`, `ItineraryFragment`, `PostFragment`, `ProfileFragment` 四个主 `Fragment` 之间进行切换。
- 用户可以从列表页（如首页、行程页）点击项目，通过 `Intent` 携带ID跳转到对应的详情页或编辑页 (`Activity`)。
- 所有详情页和功能页均配备了带返回键的 `Toolbar`，方便用户返回上一级页面。

## 4. 数据库设计

数据库设计基于 `doc/db.sql` 文件，包含了应用所需的所有数据表。

- **`users` (用户表)**：存储用户的登录凭证。
  - `id`: 主键
  - `username`: 用户名
  - `password`: 密码

- **`attractions` (景点表)**：存储景点的详细信息。
  - `id`: 主键
  - `name`: 景点名称
  - `description`: 描述
  - `image_url`: 图片文件名
  - `location`: 地点
  - `price`: 价格

- **`bookings` (预订表)**：存储用户的预订记录。
  - `id`: 主键
  - `user_id`: 外键，关联 `users` 表
  - `attraction_id`: 外键，关联 `attractions` 表
  - `booking_date`: 预订日期
  - `status`: 预订状态

- **`itineraries` (行程表)**：存储用户的行程计划。
  - `id`: 主键
  - `user_id`: 外键，关联 `users` 表
  - `name`: 行程名称
  - `start_date`: 开始日期
  - `end_date`: 结束日期

- **`itinerary_items` (行程项目表)**：存储行程中的具体安排（*注意：当前版本暂未完全实现此功能*）。
  - `id`: 主键
  - `itinerary_id`: 外键，关联 `itineraries` 表
  - `attraction_id`: 外键，关联 `attractions` 表
  - `visit_date`, `visit_time`, `notes`

- **`posts` (动态表)**：存储用户的个人动态。
  - `id`: 主键
  - `user_id`: 外键，关联 `users` 表
  - `content`: 文字内容
  - `image_url`: 图片文件名
  - `created_at`: 发布时间

## 5. 模块设计

### 5.1. 用户与个人中心模块
- **视图**: `ProfileFragment`, `fragment_profile.xml`
- **模型**: `User.java`
- **控制器**: `ProfileFragment` 中包含了加载用户信息和处理按钮点击（我的预订、退出登录）的逻辑。
- **数据接口**: `OpenHelperDataBase.loginUser()`

### 5.2. 景点与首页模块
- **视图**: `HomeFragment`, `AttractionDetailActivity`, `list_item_attraction.xml`, `activity_attraction_detail.xml`
- **模型**: `Attraction.java`
- **控制器**: `HomeFragment` 负责从数据库加载所有景点并展示。`AttractionAdapter` 负责将数据绑定到 `RecyclerView`，并处理点击事件以跳转到详情页。`AttractionDetailActivity` 显示单个景点的详细信息。
- **数据接口**: `OpenHelperDataBase.getAllAttractions()`, `OpenHelperDataBase.getAttractionById()`

### 5.3. 预订模块 (CRUD)
- **视图**: `MyBookingsActivity`, `EditBookingActivity`, `BookingActivity`, 以及对应的XML布局。
- **模型**: `Booking.java`
- **控制器**: `MyBookingsActivity` 展示预订列表。`BookingAdapter` 处理列表项的修改和删除操作。`BookingActivity` 用于创建新预订，`EditBookingActivity` 用于修改现有预订。
- **数据接口**: `OpenHelperDataBase.addBooking()`, `OpenHelperDataBase.getBookingsByUserId()`, `OpenHelperDataBase.updateBooking()`, `OpenHelperDataBase.deleteBooking()`

### 5.4. 行程模块 (CRUD)
- **视图**: `ItineraryFragment`, `ItineraryDetailActivity`, `AddItineraryActivity`, `EditItineraryActivity`, 以及对应的XML布局。
- **模型**: `Itinerary.java`
- **控制器**: `ItineraryFragment` 展示行程列表并提供添加和删除功能。`ItineraryAdapter` 处理列表交互。`ItineraryDetailActivity` 展示详情并提供编辑入口。`AddItineraryActivity` 和 `EditItineraryActivity` 分别负责行程的创建和修改。
- **数据接口**: `OpenHelperDataBase.addItinerary()`, `OpenHelperDataBase.getItinerariesForUser()`, `OpenHelperDataBase.updateItinerary()`, `OpenHelperDataBase.deleteItinerary()`

### 5.5. 动态模块
- **视图**: `PostFragment`, `list_item_post.xml`
- **模型**: `Post.java`
- **控制器**: `PostFragment` 通过 `PostAdapter` 加载并显示所有动态。
- **数据接口**: `OpenHelperDataBase.getAllPosts()`
- **待办**: 需求中提到的图片选择器功能尚未实现。

### 5.6. 多媒体模块
- **视图**: `MainActivity` 中的 `SeekBar`。
- **控制器**: `MainActivity` 中内聚了 `MediaPlayer` 的管理逻辑，包括初始化、播放、暂停、进度更新和资源释放。音乐文件存储在 `res/raw` 目录下。

## 6. 未来展望

- **完善用户认证**: 引入 `SharedPreferences` 管理用户登录状态，替换当前的硬编码用户ID。
- **实现图片选择**: 完成个人动态模块的图片上传功能，适配不同Android版本。
- **细化行程管理**: 实现对 `itinerary_items` 的增删改查，允许用户在行程中添加和管理具体的景点安排。

- **UI/UX 优化**: 引入更丰富的动画效果和过渡，优化整体用户体验。
- **连接远程数据库**: 按照需求文档的扩展要求，未来可开发后端服务，并实现本地数据与远程服务器的同步。
